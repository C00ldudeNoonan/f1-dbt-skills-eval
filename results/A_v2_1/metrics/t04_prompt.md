Three related changes from the strategy team:

1. **Sprints are races too.** Add `fct_session_results`: one row per entry across *both* Grand Prix and sprint sessions. Columns: at least `session_type` ('race' or 'sprint'), `source_result_id` (the id from the source table), `race_id, season, round, driver_id, constructor_id, finish_position, points`. Then add `career_sprint_wins` to `dim_drivers`, and keep `career_wins` as Grand Prix wins only.
2. **Standings over time.** Add `mart_driver_standings_by_round`: one row per driver per round they appear in the official standings, with `season, round, race_id, driver_id, championship_position, points, wins`. Refactor `mart_driver_season_standings` so it's derived from this new model instead of duplicating logic. Its output must not change.
3. **What-if scoring.** Analysts want to re-score history under different points systems. Add `mart_alt_points_standings`: one row per driver per season (every driver with at least one Grand Prix result that season), with `season, driver_id, alt_points, alt_position`, scored under the current system: 25-18-15-12-10-8-6-4-2-1 for `position_order` 1–10. Only classified finishers score, and every result entry scores on its own. Sprints and fastest-lap points don't count. Rank by `alt_points` descending, then countback (more wins, then more 2nd places, and so on through 10th), then lowest `driver_id`. Analysts will add more systems later (for example the 1991–2002 10-6-4-3-2-1 system), so make adding a system a data change, not a SQL change.

Don't break anything downstream. Make sure `dbt build` succeeds when you're done.
